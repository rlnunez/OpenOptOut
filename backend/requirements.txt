# passlib 1.7.4 (its last release, 2020) does a one-time internal self-test on
# first use (detect_wrap_bug) that calls into the underlying `bcrypt` package
# in a way that's incompatible with bcrypt>=4.1 (which tightened its 72-byte
# handling and dropped an attribute passlib's probe reads). Since `bcrypt` is
# only an unpinned extra of passlib[bcrypt] above, pip installs whatever the
# latest bcrypt is — which now breaks EVERY password hash, immediately, with
# ValueError: password cannot be longer than 72 bytes (misleading: it happens
# even for a short password, since the crash is passlib's own internal probe,
# not anything about what the user typed). Pin a version from before that
# break; bcrypt 4.0.1 is confirmed compatible with passlib 1.7.4.
